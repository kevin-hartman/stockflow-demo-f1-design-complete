# StockFlow Information Architecture

## Screens

| Screen | Route | Purpose | Root `data-testid` |
|---|---|---|---|
| Stock (home) | `/` | Stock-by-location table for the warehouse, location filter + search, scan zone; badges per row | `stock-home` (`stock-table`, `stock-row-<sku>-<location>`, `scan-zone`, `empty-state`) |
| SKU detail | `/skus/:sku` | Narrow page: SKU info, quantity per location, tracking code / batch / serial ("not tracked" when absent), recent movements, adjust action | `sku-detail` (`sku-locations`, `adjust-form`) |
| Receive | `/receive` | Inbound receipt form: supplier, SKU (scan or type), quantity, location | `receive-form` |
| Pick | `/pick` | Outbound pick form: order ref, SKU, quantity, location; refuses overcommit inline | `pick-form` |
| Adjust | `/skus/:sku/adjust` (or inline on detail) | Stock adjustment with reason; inline green flash on success | `adjust-form` |
| Confirmation | `/receive/done`, `/pick/done` | Post-submit summary + next actions (another / back to stock) | `confirmation` |
| Cycle count (later) | `/count` | Count a location and reconcile with system quantity | `count-form` |
| File stock | `/stock/new` | File (create-or-update) one stock record per (sku, location) — S1 AC1–AC5. `form_input` fields with persistent labels: SKU (text, `field-sku`), Location (text, `field-location`), Tracking code (text, `field-tracking-code`), Quantity (number, min 0, `field-quantity`) required; Par level / Batch / Serial optional (`field-par-level`, `field-batch`, `field-serial`; blank → stored absent, shown "not tracked"). Submit `btn--primary` (`file-stock-submit`, disabled + spinner while pending). Success: inline `confirmation` card naming sku/location/tracking/qty and whether "Filed" (new) or "Updated" (re-file of same pair, in place, no error page) + `toast-success`; stays on screen with "File another" + "View stock" links. Errors: `field-error-<name>` naming the missing field (sku/location/tracking-code/quantity) or negative quantity (`field-error-quantity`), `alert-error` summary; no record changed | `file-stock-form` (`file-stock-confirmation`) |
| Tracking-code lookup | `/` (`?code=`) — scan zone on Stock home | Find one stock record by tracking code — S2 AC1–AC4. Control: a labelled text search box (`lookup-input`, `form_input`, autofocused, type=search, no option list; hardware scanner types + sends Enter) with submit `btn--primary` (`lookup-submit`); Enter or button submits; `?code=` prefills + runs it. States: idle; found → `lookup-result` `card` showing SKU, location, tracking code, quantity (`lookup-result-sku`, `lookup-result-location`, `lookup-result-tracking-code`, `lookup-result-quantity`) and par level / batch / serial, each showing "not tracked" when absent (`lookup-result-par-level`, `lookup-result-batch`, `lookup-result-serial`), never blank, matching table row highlighted (`stock-row-<sku>-<location>`), shown ≤~200ms after scan (served from cached lookup, no full reload); not found → `empty-state` `lookup-not-found` "No record found for U" inside the scan zone (`role="status"`, no error page); request failure → `toast-error` | `lookup` (`lookup-input`, `lookup-submit`, `lookup-result`, `lookup-result-sku`, `lookup-result-location`, `lookup-result-tracking-code`, `lookup-result-quantity`, `lookup-result-par-level`, `lookup-result-batch`, `lookup-result-serial`, `lookup-not-found`) |
| Stock list + SKU detail (S3) | `/` and `/skus/:sku` | S3 AC1–AC4. **Stock list** (`stock-table`, `stock-table` class, on `/`): one row per (sku, location) record `stock-row-<sku>-<location>` with cells `stock-cell-sku` (link → `/skus/:sku`, `stock-link-<sku>`), `stock-cell-location`, `stock-cell-tracking-code`, `stock-cell-quantity` (mono, right-aligned), `stock-cell-par-level`, `stock-cell-batch`, `stock-cell-serial` — absent values render the text "not tracked" (`not-tracked`, muted), never blank; same SKU appears once per location. No records → `empty-state` (`stock-empty`) heading "No stock recorded yet" + CTA **File stock** → `/stock/new`, never a blank table or error. **SKU detail** (`sku-detail`, `page` + `card`): heading `sku-detail-title` = SKU; `sku-locations` table lists ONLY that SKU's records, each `sku-location-row-<location>` with `sku-location-location`, `sku-location-quantity`, `sku-location-tracking-code`, `sku-location-par-level`, `sku-location-batch`, `sku-location-serial` ("not tracked" when absent); unknown SKU → `empty-state` (`sku-not-found`) + link back to Stock. Read-only, no new interactive controls beyond the SKU links | `stock-home`, `sku-detail` |
| Inline adjust + adjustment history (S4) | `/` (stock-table rows) and `/skus/:sku` (`sku-locations` rows) | S4 AC1–AC5. **Inline adjust form** per row `adjust-row-<sku>-<location>` (`form_input` + `btn--secondary`): New quantity (number input, min 0, `adjust-quantity-<sku>-<location>`), Actor (text input, required, persistent label, `adjust-actor-<sku>-<location>`), submit `adjust-submit-<sku>-<location>` (disabled + spinner while pending). States: optimistic — row `stock-cell-quantity` shows the new value at once, no reload; confirmed — row shows the server-returned quantity + green flash + `toast-success`; below-zero → `field-error-quantity` naming Quantity, row reverts to Q; blank actor → `field-error-actor` naming Actor, quantity unchanged; server failure → persistent `toast-error`, row reverts. **History** button `history-toggle-<sku>-<location>` (disclosure toggle, `aria-expanded`, states collapsed/expanded) opens `adjustment-history` panel (`card` + `stock-table` class): rows `history-entry-<n>` in time order with `history-timestamp`, `history-actor`, `history-qty-before`, `history-qty-after` (mono); no entries → `empty-state` `history-empty` "No adjustments yet". Entries are read-only: NO edit/delete controls rendered (AC5 immutability; any API edit/delete attempt is refused and the panel still shows original values) | `adjust-row-<sku>-<location>`, `adjustment-history` |
| About | `/about` | Product voice + version | `about-page` |

Shared seams: `toast-region`, `toast-success`, `toast-error`, `alert-error`, `field-error-<name>`, `loading`.

## Navigation

- Navbar (`navbar`): brand (warehouse icon + "StockFlow") → `/`; links **Stock** `/`, **Receive** `/receive`, **Pick** `/pick`, **File stock** `/stock/new`, **Count** `/count` (when built), **About** `/about`; active link in brand red.
- Every screen is a `<Route>` in `client/src/App.tsx`. SKU detail is reached from a stock-table row (SKU link) or a scan; Adjust from the detail page; confirmations only via form submit, each linking back to Stock.
- File stock (`/stock/new`) is a `<Route>` in `App.tsx`, reached from the navbar **File stock** link (`nav-file-stock`) and the Stock home empty-state CTA.
- Tracking-code lookup lives in the Stock home scan zone (`/`), reached via navbar **Stock** or brand; deep-linkable as `/?code=<code>`. The found result links SKU → `/skus/:sku`.
- Stock list is the home route `/` (navbar **Stock** / brand); each `stock-link-<sku>` navigates to `/skus/:sku`; SKU detail has a "Back to stock" link (`back-to-stock`) → `/`. The stock-list empty-state CTA links to `/stock/new`.
- Inline adjust + history are in place on each Stock list row (`/`) and SKU detail location row (`/skus/:sku`); no route change, no reload.
- Client-side routing only; no full-page reloads.

## User flows

1. **See stock** (story: retrieve stock): `/` → table loads (loading → rows or empty-state "No stock at this location — receive an inbound shipment") → filter by location → click SKU → `/skus/:sku`.
2. **Scan to update** (floor primary): `/` scan zone → scan barcode → success: row flashes + updates in place, green scan zone; failure (unknown/locked): red scan zone + persistent error toast.
3. **Receive inbound**: navbar Receive → fill supplier/SKU/qty/location → submit (button disabled + spinner) → `/receive/done` confirmation; invalid → inline field-named error.
4. **Pick outbound**: navbar Pick → SKU/qty/location → submit → confirmation; overcommit → inline `field-error-quantity` naming available qty.
5. **Adjust stock**: SKU detail → adjust (qty + reason) → inline green flash + success toast, row updated; failure → persistent error toast, value reverted.
6. **Multiple locations**: SKU detail lists each location's quantity with status badge.
7. **Cycle count** (later): Count → choose location → enter counts → reconcile variance → confirmation.
8. **File a stock record** (S1): navbar File stock → `/stock/new` → enter SKU, location, tracking code, quantity (optional par/batch/serial blank OK) → submit → inline `file-stock-confirmation` ("Filed") + success toast (AC1, AC3); re-file same sku+location with new qty/code → confirmation "Updated", one record, no error page (AC2); missing required field → `field-error-<name>` naming it, nothing saved (AC4); negative quantity → `field-error-quantity`, nothing saved (AC5).
9. **Find by tracking code** (S2): `/` → scan or type code T into `lookup-input` → submit/Enter → `lookup-result` shows SKU, location, tracking code, quantity within ~200ms of scan, row highlighted (AC1, AC2); absent par/batch/serial show "not tracked" (AC4); unknown code U → `lookup-not-found` "No record found for U", no error page (AC3).
10. **View stock list and SKU detail** (S3): navbar Stock → `/` → `stock-table` one row per (sku, location) with SKU, location, tracking code, quantity (AC1) → click `stock-link-<sku>` → `/skus/:sku` shows every location record for that SKU only, with quantity + tracking code (AC2); absent par/batch/serial read "not tracked" in both views (AC3); no records → `stock-empty` empty-state with File stock CTA (AC4).
11. **Adjust quantity in place** (S4): `/` (or `/skus/:sku`) → row's inline adjust → enter new quantity + actor → submit → row shows new qty at once, then server value + success toast (AC1); below zero → `field-error-quantity`, row reverts to Q (AC2); blank actor → `field-error-actor`, qty unchanged (AC3); open `history-toggle-<sku>-<location>` → `adjustment-history` lists timestamp, actor, before/after in time order (AC4); entries read-only, no edit/delete affordance, values unchanged after any edit/delete attempt (AC5).
